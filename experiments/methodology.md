# Методология эксперимента
## Цель исследования
Сравнительный анализ вычислительных затрат алгоритмов хеширования паролей bcrypt, PBKDF2-HMAC-SHA256 и Argon2id, а также исследование влияния их настраиваемых параметров на время выполнения операций хеширования и проверки паролей.

В ходе исследования решаются следующие задачи:

* Определение зависимости времени хеширования от параметров каждого алгоритма.
* Сравнение времени создания и проверки парольных хешей.
* Оценка стабильности результатов при многократных измерениях.
* Анализ полученных зависимостей и ограничений экспериментального сравнения

## Экспериментальная среда

Эксперимент реализован на языке Python с использованием библиотек bcrypt, argon2-cffi, hashlib, numpy, pandas и matplotlib.

Измерения выполняются последовательно в одной вычислительной среде. Характеристики операционной системы, процессора, объёма оперативной памяти и версии Python сохраняются в файле results/system_info.txt.

Для исследования используется набор из 1000 паролей длиной от 8 до 20 символов, состоящих из латинских букв, цифр и специальных символов. Пароли генерируются псевдослучайным образом с использованием заданного значения seed (по умолчанию — 42), что обеспечивает воспроизводимость исходных данных.

## Исследуемые параметры

В эксперименте рассматриваются следующие конфигурации алгоритмов:

| Алгоритм | Изменяемый параметр | Исследуемые значения |
 :--- | :---: | ---: |
| bcrypt | cost | 4, 6, 8, 10, 12 |
| Argon2id | memory_cost | 16, 32, 64, 128 МиБ |
| Argon2id | time_cost | 1, 2, 3, 4, 5 |
| PBKDF | Количество итераций | 10 000, 50 000, 100 000, 200 000, 500 000 |

При исследовании memory_cost у Argon2id фиксируется time_cost=3, а при исследовании time_cost — memory_cost=64 МиБ. В обоих случаях используется parallelism=4.

При изменении одного параметра остальные параметры алгоритма остаются постоянными.

##  Порядок проведения эксперимента

Перед началом измерений выполняется генерация тестовых паролей.

Для каждой конфигурации алгоритма проводится один предварительный вызов функции хеширования с целью прогрева, после чего выполняется 100 последовательных измерений с использованием тестовых паролей.

Продолжительность каждой операции определяется функцией time.perf_counter(). Измеряемый интервал включает выполнение соответствующей функции хеширования.

Дополнительно проводится исследование времени проверки паролей для следующих конфигураций:

* bcrypt — cost=12;
* PBKDF2-HMAC-SHA256 — 500 000 итераций;
* Argon2id — memory_cost=64 МиБ, time_cost=3, parallelism=4.

Для каждой конфигурации выполняется 30 повторных измерений проверки заранее сформированного хеша.

## Обработка результатов

Для каждой исследованной конфигурации рассчитываются следующие статистические показатели:

* Медианное время — основной показатель продолжительности операции.
* Стандартное отклонение — характеристика разброса измерений.
* Первый и третий квартили (Q1 и Q3) — границы центральных 50% измерений.
* Коэффициент вариации (CV) — относительная оценка разброса времени выполнения.

Результаты сохраняются в CSV-файлы каталога results/. Отдельные измерения также сохраняются для возможности повторной статистической обработки.

На основе полученных данных строятся графики зависимости времени хеширования от параметров алгоритмов, диаграмма сравнения времени хеширования и проверки, а также диаграмма относительного разброса измерений.

Графики сохраняются в каталоге figures/.

## Воспроизводимость и ограничения

Воспроизводимость исходных данных обеспечивается фиксированным значением seed. При повторных запусках с одинаковыми параметрами ожидается сохранение основных зависимостей, однако точное совпадение времени выполнения не гарантируется.

На результаты могут влиять фоновая нагрузка операционной системы, изменение частоты процессора, состояние кеша и особенности работы оперативной памяти.

В эксперименте не выполняется инструментальное измерение фактического пикового потребления оперативной памяти. Для Argon2id исследуется влияние заданного параметра memory_cost на время выполнения.

Кроме того, исследуемые конфигурации разных алгоритмов не являются эквивалентными по криптографической стойкости. Поэтому сравнение времени характеризует производительность выбранных конфигураций, а не абсолютное преимущество одного алгоритма над другим.

Полученные результаты применимы прежде всего к используемой экспериментальной среде и должны учитываться совместно с требованиями безопасности при выборе алгоритма хранения паролей.
